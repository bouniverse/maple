# 검증 대장 (Verification Ledger) — 공식 신뢰도 단일 진실 소스

> **목적**: 모든 공식·상수·모델이 "어떻게 검증됐는지" 한눈에. 수학 의존 리스크를 추적으로 관리.
> **갱신 주체**: 측정 시 `measurement-analyst`, 분기 판단 시 메인(오케스트레이터).
> **실측 채점 사례**: `검증사례-16-5.md` (성장후 방어곡선·크뎀·34%갭 3중 채점 — 첫 적용례).
> **상태 범례**: ✅ 실측확정 / 🟡 부분검증·가설 / 🔴 미검증

## 3대 검증 레이어 (대표님 정의)
1. **실측 채점** — 모든 공식 결론은 게임 실측으로 대조(예측 vs 실측, 오차 기록).
2. **advisor 교차** — 중요 분기·갭은 opus advisor로 교차검증(✓ 표시).
3. **엔진 테스트** — 확정 결론은 `realDamage.test.mjs` 골든값으로 박제 → 회귀/신규측정 충돌 자동 감지(비용절감).

## 운영 규칙
- 새 측정 결론이 나오면: ① 실측 오차 기입 → ② 상태 갱신 → ③ ✅면 테스트 골든값 박제(⬜→✓) → ④ 중요분기면 advisor(✓).
- **신규 측정이 기존 ✅ 항목과 충돌하면** = 둘 중 하나가 틀림 → 테스트가 깨지거나 대장 모순으로 즉시 감지 → 재측정/재검증.
- 🔴·🟡 항목은 계산기 절대값에 쓰기 전 반드시 승격 또는 [가설] 표기 노출.
