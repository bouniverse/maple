## 2. ⚠ 미결정 — 다음 세션 첫 액션

**엔진이 두 모델로 갈라져 있음:**
- `realDamage.mjs` = 합산공격력 + perLevel (옛 모델, 미수정)
- `validate-necklace.mjs` = 최종공격력 직접 (신 모델, 검증용으로 새로 짬)

**할 일: 본 엔진(`realDamage.mjs`)을 통합한다.**
- 스냅샷 비교 → `최종 공격력` 직접 입력 (perLevel 불필요)
- 델타 입력("스킬레벨 +9만 변경") → perLevel 모델 **여전히 필요** (양자택일 아님, 용도 분리)
- 통합 후 테스트 갱신 + 커밋.

> 대표님이 "엔진 통합 진행할까요?"에 아직 GO/STOP 답 안 하심 → **새 세션에서 먼저 확인**.

## 3. 대표님 인게임 실측 대기 (둘 중 하나면 진척)

- **A. perLevel 보정용**: 다른 옵션 고정, **3차 스킬 레벨만 ±1~2**, 변경 전/후 **최종 공격력**(+가능하면 스킬 데미지 툴팁) 기록.
- **B. 절대 정확도 검증용**: 한 버전의 **실제 인게임 한 방 데미지** 숫자 1개.
- A만 있어도 델타 입력 모드 작동, B까지 있으면 절대값 확정.
- 이유: 현재 데이터엔 실제 데미지 수치가 없고, 스킬레벨만 다른 쌍도 없어 보정·검증 불가.

## 4. 미해결 (데이터.md §5)
1. 스킬 레벨당 % (perLevel) — 미상, §3-A 실측 필요
2. 크리 기본 배율 모델 (`1+크리율×크리뎀` 평균 가정) 검증 필요
3. 방어 관통력 — 적 방어력 입력 필요, 엔진 미반영
4. 게임 화면 가로/세로 미확인 → UI 설계 블로커
5. 시스템 단계별 수치(스타포스/잠재/동료/용사의 힘) 점진 수집
